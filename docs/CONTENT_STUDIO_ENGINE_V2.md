# Content Studio Editorial Engine V2

작성일: 2026-11-02 · 방향 `studio-angles-v3`, 제작 `studio-production-v3` · 이전 단계: `docs/CONTENT_STUDIO_EDITORIAL.md`

## PHASE 1. 진단 — 왜 '기아타이거즈'에서 '삐끼삐끼'가 나왔나

| 단계 | v2 동작 | 결과 |
|---|---|---|
| WHY 웹 수집 | [배경]·[사건]·[확산 콘텐츠]·[브랜드 사례] 분류로 웹 출처 7건 | 원장이 "사건 목록" 형태 |
| 방향 생성 입력 | WHY 트리거·동기 + 원장 발췌 전문 | 방향 5개가 웹 항목 5개와 **1:1 대응**(WEB-01 기원, WEB-03·04 삐끼삐끼, WEB-02 퍼레이드, WEB-05 시구, WEB-06 스폰서) |
| 방향 평가 | `evidence_fit: grounded`를 "좋은 방향"처럼 다룸 | 자료에 붙은 방향이 우선 |
| 방향 선택 | 사용자가 아니라 **E7 실험에서 개발자가** '근거 충분'인 1번(삐끼삐끼)을 골랐다 | |
| 제작 | 원장 전체 + "research for accurate details and good stories" | 본문이 "보도는 … 소개했어요"식 출처 서술 |

결론: 어투가 아니라 **기획의 출발점**(리서치 항목 → 방향)이 문제였다. 보고서식 표현 0개는 이 문제를 잡지 못했다.

## PHASE 2. 변경한 파이프라인

```
키워드 → 모드 → [소재 중심 방향 5개] → 사용자 선택 (또는 직접 입력한 주제 그대로)
      → [방향 맞춤 자료 선별 (+선택: 방향 맞춤 웹 조사 1회)] → [스토리라인] → 슬라이드 → [품질 게이트 → 필요하면 1회 고쳐 쓰기]
```

- 방향 입력(`buildAngleContext`): 소재 기본 정보(이름·키워드·what 요약·DNA 어휘) + 리서치 **제목 목록만**. WHY 사건·원인·발췌·검색 관심도는 넣지 않는다.
- 방향 규칙: 소재에 맞는 독자 경험 유형(`angle_type`: guide·fandom·history·curation·experience·people·howto·comparison·behind·trivia) 4종 이상, 리서치 사건 하나에 기댄 방향(`research_anchor`)은 최대 2개. 위반·뻔한 제목이면 1회 재생성.
- 제작 입력(`buildProductionContext`): 소재 기본 정보 + **선택한 방향에 맞는 자료만**(방향이 인용한 근거 → 방향 글과 겹치는 자료 순, 최대 8개). 방향 맞춤 웹 조사를 켜면(`research: true`) 기존 웹 출처 수집기를 방향 초점으로 1회 호출해 실제 조회한 URL만 `AR-xx`로 추가.
- TREND REPORT는 기존 분석 전체를 그대로 쓴다.

## PHASE 3·4. 방향 다양화 · 스토리 우선

- 기아타이거즈 v3 방향: 입문(응원가부터) · 팬덤(삐끼삐끼) · 역사(광주 우승 퍼레이드) · 체험(직관 하루 코스) · 비하인드(시구) — 사건 중심 2개.
- 제작 스키마: `storyline`(슬라이드보다 먼저: beat, reader_gets) → 슬라이드마다 `specific_detail`(이 소재만의 디테일), `reader_gets`. WHY 항목 순서를 따르지 말고 독자 경험 순서(후킹 → 이해 → 이야기 → 실용 → 마무리)로.

## PHASE 5. EDITORIAL QUALITY GATE (`lib/editorial-quality.ts`, 규칙 검사)

| 검사 | 방법 |
|---|---|
| 방향 반영 | 방향 글 ↔ 제목·앞 슬라이드 2-gram 유사도 |
| 새 정보·재미 | 슬라이드 본문끼리 겹침, reader_gets 비어 있음 |
| 보도·분석 요약형 아님 | "보도는/소개했어요/에 따르면" 등 출처 서술 슬라이드 2개 이상이면 실패 |
| 소재 특이성(스왑 테스트) | 소재 이름을 지운 뒤 고유어(외부 자료·사실 주장 어휘, 일반어 제외)·고유명사·숫자·인용이 남는가 |
| 소재와의 연결 | 소재 이름이 2장 이상, 또는 표지+캡션에 |
| 문자 섞임 | 인용 밖 일본어 가나 |
| 구체적 후킹 · 저장 이유 · 사실 검증 가능 | 표지 문장, 실용 슬라이드+CTA, fact_checks |

방향 반영·보도 요약형·소재 특이성·새 정보·소재 연결·문자 섞임이 실패하면 **1회 고쳐 쓰고 더 나은 쪽**을 남긴다. 결과는 Editor Notes에 "자동 규칙 검사 n/9 (사용자 평가 아님)"으로 표시한다. AI 점수가 아니다.

검증하며 고친 게이트 결함(실측으로 발견):
1. 고유어를 모델이 쓴 `specific_detail`에서 가져오자 "다른 팀에도 통하는 팁"이 7/7 통과 → 외부 자료 어휘 + 일반어 목록으로 변경.
2. 소재 이름이 한 번도 안 나온 "스티커 바인더 일반 팁"이 통과 → '소재와의 연결' 추가.
3. 'キャ릭터', 'ゆるいかわいさ와' 같은 문자 섞임 → '문자 섞임' 추가.
4. 사용자 지정 주제 이탈을 2-gram으로 판정하자 주제를 지킨 방향 5개를 모두 이탈로 오판(불필요한 재생성 1회) → 단어·유의어 기준으로 바꿨지만 여전히 오탐·미탐이 있어 **재생성 조건에서 빼고 표시만** 한다.

## PHASE 6. 사용자 편집권

생성 전에 모드·방향·타깃·톤(프리셋+직접 입력)·형식을 고른다. **직접 정한 주제** 입력란: "이 주제로 방향 5개 제안받기"(5개 모두 그 주제의 변주) 또는 "이 주제 그대로 쓰기"(AI 제안 없이 그 주제를 방향으로). 주제는 서버 프롬프트에서 최우선 지시다.

## 남은 한계
- 규칙 검사는 문장 품질을 대신 판단하지 못한다(후킹 검사는 엄격해서 대부분 실패로 나온다; 별칭 '디카' 같은 소재 이름 변형은 키워드에 없으면 못 센다).
- 사용자 지정 주제 이탈 자동 판정은 신뢰도가 낮아 표시만 한다.
- 방향 맞춤 조사는 선택 기능(웹 검색 1회 추가). 끄면 구체 정보가 부족해 일반적인 팁이 나오기 쉽다(기아 A 1·2차).
- 헤이세이 2차·디카·치이카와처럼 고쳐 쓴 뒤에도 게이트 실패가 남을 수 있다 — Editor Notes에 그대로 표시한다.
