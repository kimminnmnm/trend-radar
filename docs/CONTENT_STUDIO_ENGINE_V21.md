# Content Studio Editorial Engine V2.1

작성일: 2026-11-02 · 제작 `studio-production-v4`, 방향 `studio-angles-v4` · 이전: `docs/CONTENT_STUDIO_ENGINE_V2.md`

## 바뀐 것

| Phase | 구현 |
|---|---|
| 1. Detail Bank | 제작 응답 안에서 슬라이드보다 먼저 `detail_bank`(디테일·사례·활용·출처 ID·검증 상태) 6~10개. 검증 상태는 서버가 출처 ID를 원장과 대조해 정한다(`verified`/`needs_check`). ID는 서버가 D1..Dn으로 다시 매기고 슬라이드의 `detail_ids`도 따라 바꾼다. 소재 이름·추상 감정·일반 조언은 디테일로 금지. 방향 맞춤 웹 조사는 기본 켬(웹 검색 1회, 끌 수 있음). |
| 2. Storyline | 본문 슬라이드마다 서로 다른 Bank 항목(`detail_ids`)과 다음 장으로 넘길 이유(`to_next`). 팁 슬라이드는 소재 고유 디테일이 있어야 한다. |
| 3. Hook | 제목 구조 분류(‹소재›,질문? / 질문 / 숫자·목록 / 대비 / 인용 / 방법 / 단언·장면). 방향 5개 중 '‹소재›, 질문?' 최대 1개, 같은 구조 최대 2개(기본값인 단언·장면은 세지 않음). 좋은 후킹인지는 규칙이 아니라 편집 리뷰가 판단. |
| 4. Quality | **A 필수 검증**(규칙): 사실 정확성·주제 일치·언어 일관성(인용 「」 밖 가나·한자)·근거 ID 유효성·중복. **B 편집 신호**(규칙, 참고): 소재 고유성(스왑 테스트)·Detail Bank 활용·출처 서술·제목 구조·슬라이드 가치. **편집 리뷰**(AI 1회): 후킹·고유성·전개·저장·공유·문체 1~5점(참고 점수, 사용자 평가 아님) + 문제 슬라이드·제목만 부분 수정. 고친 슬라이드가 새 문제를 만들면 그 슬라이드만 초안으로 되돌린다(추가 호출 없음). |

## 실측 호출
제작 9회(각 회차 = 방향 맞춤 웹 조사 1 + 제작 1 + 편집 리뷰 1), 방향 2회(+ 구조 분류 오판으로 인한 불필요한 재생성 2회). 실패했던 세 소재는 V2 방향을 재사용해 방향 호출을 하지 않았다.

## 발견하고 고친 것
- 제목 구조 분류의 기본값(단언·장면)을 몰림으로 세어 구체적인 제목 4개를 오판 → 기본값 제외.
- 편집 리뷰가 고친 슬라이드에 새 문제를 넣음(일본어, 조사 수치형) → 슬라이드별 되돌림.

## 남은 한계
- 주제 일치: 헤이세이·디카는 고쳐 쓴 뒤에도 소재 틀을 드러내지 않았다. 규칙은 잡지만 리뷰가 고치지 못했다.
- '출처 서술' 신호가 "보고됐어요"·"조사에서는" 같은 조사 보고형 문장을 못 잡는다(치이카와 2차).
- 리뷰 점수는 같은 모델의 자기 평가 성격이 있어 3~4점에 몰린다. 참고용이다.
- 방향 맞춤 조사를 끄면 V2처럼 일반 팁이 나오기 쉽다.
- 비용: 제작 1회가 호출 3회(조사·제작·리뷰)로 늘었다.
