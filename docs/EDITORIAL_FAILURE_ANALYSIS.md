# EDITORIAL ENGINE V3 · E0 — 실패 분석(코드 원인)

작성일 2026-11-04 · 코드 변경 없음

## 0. 조사 범위와 방법

- **읽은 코드**
  - `lib/openai-editorial.ts`: 방향(Angle) 제안과 제작용 컨텍스트
  - `lib/openai-production.ts`: 제작 프롬프트와 편집 리뷰
  - `lib/editorial.ts`: 콘텐츠 모드와 방향 검증
  - `lib/editorial-quality.ts`: 품질 게이트
  - `lib/editorial-lock.ts`: T6 Context Lock
  - `lib/image-brief.ts`: T7 이미지 의미 블록
  - `lib/discovery.ts`: 현상 추출
  - `components/studio-production.tsx`: Studio 진입 경로
- **"실제 출력"은 저장된 실측 기록에서 인용했다.** 새로 API를 호출하지 않았다.
  - `tests/fixtures/editorial-engine-v2.json`, `editorial-engine-v21.json`, `editorial-studio.json`
  - `context-lock-t6.json`, `e2e-t8.json`, `studio-production.json`
- **원인 표시**
  - **[확인]**: 코드에서 직접 확인했다.
  - **[가설]**: 코드상 그럴 가능성이 있지만, 비교 실험으로 확인하지 않았다.

## 1. 데이터 흐름 요약(현재)

```
Discover / WHAT'S HAPPENING NOW? ──(현상 선택)──┐
                                                ▼
키워드 WHY·DNA ──► Studio 진입 ──► 콘텐츠 모드 ──► 방향 5개 제안 ──► 사용자 선택 ──► 제작(카드뉴스) ──► 품질 게이트 ──► 편집 리뷰(부분 수정)
                   │                                                                     │
                   └ ?trend= (키워드)      : Context Lock 없음                          └ 슬라이드별 image_prompt → (T7 의미 블록) → 이미지 생성
                   └ ?phenomenon= (현상)   : Context Lock 있음
                   └ ?creative= / 사용자 주제 : Context Lock 없음
```

**핵심 구조 문제 [확인]**
- 구체적 현상이 제작까지 전달되는 것은 **`?phenomenon=` 경로뿐**이다.
  - 근거: `studio-production.tsx`의 `phenomenon` 분기와 `buildContextLock`. 잠금 정의는 `editorial-lock.ts`.
- 키워드 경로(`?trend=`), Trend Lab·Collision 경로, 사용자 주제 경로에서는 모델이 다음 두 가지만 받는다.
  - 소재 이름, 키워드, WHY 요약 1개(`subjectBasics.what`), DNA 속성 단어
  - 리서치 **제목 목록**
- 이 경로들에서는 WHAT'S HAPPENING NOW?가 찾은 **세부 현상 목록이 방향 제안 입력에 들어가지 않는다**(`buildAngleContext`). 그래서 모델이 할 수 있는 일은 "키워드를 소개하는 것"이 된다.

## 2. 실패 패턴별 분석

### FAILURE 01 — GENERIC EXPLANATION
- **발생 조건:** Context Lock 없이 키워드로 들어온 경우, 리서치가 적은 소재.
- **원인**
  1. [확인] 방향 제안 지시가 "SUBJECT FIRST: start from the subject itself … a total beginner, a fan, someone nostalgic"이다(`openai-editorial.ts` `angleInstructions`). 소재에서 출발하라고 할 뿐, **세부 현상에서 출발하라는 지시가 없다.**
  2. [확인] 위 1항의 구조 문제: 현상 목록이 입력에 없다.
  3. [확인] 스왑 테스트(`isGenericSentence`)는 **편집 신호(참고)**일 뿐 필수 검증이 아니다(`editorial-quality.ts` "B. 편집 신호"). 일반 문장이 남아도 통과한다.
- **실제 출력:** v2 `kiaA` 3장 "동작은 옆 사람을 봐요 — 응원 동작이 낯설면 주변 관중의 타이밍을 먼저 살펴봐요." 어느 팀·공연에도 통하는 문장이다.
- **개선 방향:** 방향 제안 입력에 세부 현상 후보(이미 있는 Discovery 결과)를 넣고, "현상 하나를 고르지 않은 방향"을 신호가 아닌 검증 대상으로 둔다(E1).
- **회귀 테스트:** 저장된 기록(fixture)의 슬라이드를 품질 게이트에 넣었을 때, 다른 소재에도 통하는 슬라이드가 2장 이상이면 "필수 실패"로 잡히는지 확인한다.

### FAILURE 02 — SUBJECT DRIFT
- **발생 조건:** 선택한 방향과 다른 리서치 사건이 강할 때, 사용자 주제가 짧을 때.
- **원인**
  1. [확인] Context Lock이 있으면 금지 이탈 규칙(역사·입문·구매·반대 방향)으로 막는다(T6, `editorial-lock.ts` `driftMatcher`). **잠금이 없으면 해당 검사가 없다.**
  2. [확인] 사용자 주제 이탈 검사(`isOffTopic`)는 "확인 필요" 표시만 하고 재생성 조건이 아니다(`editorial.ts` 주석).
- **실제 출력**
  - T6 before: 방향이 "아바타 룩 하나, 현실 화장 3단계"처럼 하우투로 흘렀다.
  - 잠금 전 KIA: "기아 타이거즈 검색 관심도, 무엇이 보였을까?"(리포트 모드 결과 — 사용자가 원한 주제가 아님)
- **개선 방향:** 잠금이 없는 경로에서도 "선택한 방향의 핵심 대상"을 최소 잠금(경량 Lock)으로 만들어 같은 검사를 적용한다(E1).
- **회귀 테스트:** 잠금 없는 방향에 "역사·입문·구매" 문장을 넣은 기록이 이탈로 잡히는지.

### FAILURE 03 — FAKE SPECIFICITY
- **발생 조건:** 리서치가 부족한데 Detail Bank를 6~10개 채우라는 지시를 받았을 때.
- **원인**
  1. [확인] `DETAIL_BANK` 지시가 "collect 6-10 details … from RESEARCH_FOR_ANGLE first and **well-established public knowledge second**"다. 근거 없는 '일반 지식' 디테일이 허용된다(`openai-production.ts`).
  2. [확인] 서버는 Detail Bank 항목의 근거를 판정하지만(verified/needs_check), **needs_check 디테일을 슬라이드에 쓰는 것은 막지 않는다.** 품질 게이트의 "Detail Bank 활용"도 편집 신호다.
  3. [가설] 디테일 개수 하한(6개)이 모델에게 "채워야 할 칸"으로 작동해, 그럴듯한 고유명사(캐릭터명·제품명)를 만들게 한다.
- **실제 출력:** v2.1 헤이세이 "스티커 3장으로 시작하는 취향 바인더"는 캐릭터 이름(타레판다·코게빵·마메고마·시즈쿠짱)과 제품 구성(박리지 20페이지 등)을 나열한다. 기록에서 각 항목의 근거 여부를 슬라이드 단위로 확인하지 못했다(**검증 필요**).
- **개선 방향:**
  - 근거가 없는 디테일은 "검증 필요" 배지를 붙여야만 슬라이드에 쓸 수 있게 한다.
  - 디테일이 부족하면 개수를 채우지 말고 장수를 줄이게 한다(E3).
- **회귀 테스트:** 근거 없는 고유명사를 넣은 기록에서, 해당 슬라이드가 검증 필요 표시 없이 통과하지 않는지.

### FAILURE 04 — REPETITIVE SLIDES
- **발생 조건:** 현상이 하나의 요소(예: 눈매)에 집중될 때, 디테일이 부족할 때.
- **원인**
  1. [확인] 중복 검사는 본문 유사도 0.45 이상 또는 **완전히 같은** detail_ids일 때만 잡는다(`editorial-quality.ts` duplicate). 같은 정보를 다른 말로 쓰면 통과한다.
  2. [가설] 스토리라인 단계에 "슬라이드별로 새로 더하는 정보"를 명시하는 칸(reader_gets)은 있지만, 비어 있지 않은지만 본다(flow 신호).
- **실제 출력:** T6 after 2~5장(속눈썹 → 네온 색·라인 → 그래픽 → 입술). 요소는 바뀌지만 "현실 재현에서도 포인트가 돼요"라는 같은 결론을 반복한다.
- **개선 방향:** 스토리보드(E2)에서 슬라이드마다 `new_information` 한 줄을 받고, 앞 슬라이드들과 겹치는지 검사한다.
- **회귀 테스트:** T6 after 기록에서 "새 정보" 판정이 2~5장 중 일부를 반복으로 표시하는지(기준선 기록).

### FAILURE 05 — WEAK READER VALUE
- **원인**
  1. [확인] 방향의 `reader_benefit`과 슬라이드의 `reader_gets`는 모델이 채운다. 서버는 **비어 있는지만** 본다(flow 신호).
  2. [확인] 리포트 모드는 의도적으로 분석 결과를 전달한다(`reportInstructions`). 사용자가 원치 않는데 리포트형이 나오면 독자 가치가 사라진다.
- **실제 출력:** `editorial-studio.json` KIA before(리포트형). "10월 지수는 100", "상승 원인은 확인 불가"처럼 독자가 할 수 있는 것이 없다.
- **개선 방향:** E1 브리프에서 독자 가치를 유형으로 받는다(알게 됨·할 수 있음·고를 수 있음·공감·저장 리스트). 그 유형에 맞는 증거(장소·순서·비교 기준)가 있는지 검사한다.

### FAILURE 06 — VISUAL DISCONNECTION
- **원인**
  1. [확인] 이미지 프롬프트는 모델이 슬라이드마다 쓰고, T7 의미 블록이 앞에 붙는다(`image-brief.ts`). **잠금이 없으면** 주체가 제목(`input.title`)이 되고 행동·대상 칸이 비어, 주제의 일반 이미지가 나오기 쉽다.
  2. [확인] 품질 게이트에 **이미지와 슬라이드 메시지의 일치 검사가 없다.**
  3. [가설] `visual_direction`과 `image_prompt`가 같은 모델 호출에서 함께 만들어져, 문구가 바뀌어도(편집 리뷰 패치) 이미지 프롬프트는 갱신되지 않는다. `applyPatches`는 headline·body만 바꾼다 — [확인].
- **개선 방향:** E2에서 슬라이드마다 "보여 줄 장면(주체·행동·대상)"을 문구보다 먼저 정한다. 패치로 문구가 바뀌면 이미지 브리프도 다시 만든다.

### FAILURE 07 — REPORT LANGUAGE
- **원인**
  1. [확인] `REPORT_PHRASES`(9개)와 `SOURCE_NARRATION` 정규식으로 잡는다. 하지만 "조사에서는 ~로 정의했어요", "~로 보고됐지만" 같은 **조사·통계 서술은 목록에 없다.**
  2. [확인] 출처 서술은 편집 신호(1장까지 허용)다.
- **실제 출력:** v2.1 치이카와 4~5장 "2023년 조사에서는 ‘좋아하는 캐릭터’ 문항에서 치이카와를 고른 사람을 치이카와 팬으로 정의했어요", "검색자 가운데 20~40대 비중이 높았다고 보고했어요". 매거진이 아니라 조사 요약이다.
- **개선 방향:** 통계·조사 문장은 "독자가 이걸 알면 무엇이 달라지는가"를 통과할 때만 쓰게 한다. 리뷰 기준에 "리포트 문체"를 명시한다.

### FAILURE 08 — EVIDENCE MISUSE
- **원인**
  1. [확인] 이미지는 막고 있다: `EVIDENCE_GUARD`(가짜 스크린샷·실사 금지), AI 라벨, REAL REFERENCE는 복제하지 않음.
  2. [확인] **문장 쪽 1인칭 체험 금지 규칙이 제작 프롬프트에 없다.** `openai-production.ts`에 1인칭·체험 관련 규칙이 없다(검색 결과). 바이럴·인기 표현 금지도 WHY 분석(`openai-analysis.ts`)과 잠금의 EMERGING 상태에만 있다.
- **실제 출력:** 기록된 결과에서 1인칭 체험 문장은 발견하지 못했다. 위험은 미발생 상태다(**레퍼런스 03·04 유형을 요청받으면 발생 가능 — 가설**).
- **개선 방향:** 제작 프롬프트와 필수 검증에 "체험 1인칭·인기 주장" 규칙을 추가한다(E3·E4).

### FAILURE 09 — GENERIC HOOK
- **원인**
  1. [확인] 막는 장치: `GENERIC_TITLE_PATTERNS`(10개)와 제목 구조 몰림 검사. 효과는 있었다.
  2. [확인] 다만 패턴을 막으면 다른 틀로 옮겨 간다는 점이 주석에 기록돼 있다("v2 '어디서…' → v3 '뭐부터…'").
- **실제 출력**
  - v2 방향: "헤이세이 레트로, 뭘 보면 될까?", "치이카와 팝업, 뭐부터 볼까", "미쿠 협업 굿즈, 어디부터 볼까?"
  - v2.1 이후: 개선됨. 예: "발레 슈즈가 1941년 거리로 나온 순간"
- **개선 방향:** 금지 목록 대신, 제목에 브리프의 '핵심 디테일'이 들어갔는지를 본다(제목 ↔ 대표 이미지 ↔ 디테일 일치, E4).

### FAILURE 10 — FORCED HISTORY
- **원인**
  1. [확인] 방향 유형 목록에 `history`가 있다(`editorial.ts` `angleTypes`).
  2. [확인] 사용자 주제가 없으면 **서로 다른 유형 4개 이상**이 아닐 때 재생성한다(`needsAngleRegeneration`의 `typeCount < 4`). 다양성을 강제하는 과정에서 history·guide가 거의 항상 포함된다.
  3. [확인] 방향 제안 예시가 "Example for a baseball team: a beginner's guide …, **the club's history**, a first stadium-visit guide, stadium gear and food"다(`openai-editorial.ts`). **FAILURE 10과 KIA 실패 사례를 프롬프트가 직접 예시로 준다.**
  4. [확인] CULTURE DIGGING 모드 설명에 "역사"가 들어 있다(`contentModeInfo.digging`, `modeGuide.digging`).
  5. [확인] `FACT_RULE`이 "well-established public knowledge"를 허용해 창단일·우승 연도 같은 백과사전 사실이 슬라이드를 채운다.
- **실제 출력**
  - 사용자 주제·잠금 없이 만들어졌고 유형(angle_type)이 기록된 방향 세트 **7개 모두**에 history 방향이 있다.
    - v2: KIA·보컬로이드·헤이세이·디지털카메라·치이카와
    - v2.1: 발레코어·레트로 게임
  - 유형이 기록되지 않은 이전 Studio 기록(KIA)에도 "기아 타이거즈, 어디서 왔을까?"가 있다.
  - 반대로 사용자 주제가 있는 세트(KIA 사용자 주제)와 잠금이 있는 세트(T6)에는 history 방향이 없다. 잠금·주제가 이 실패를 줄인다는 정황이다.
  - 입문 가이드 슬라이드에도 역사가 섞인다. v2 `kiaA` 2장 "팀의 출발부터 알아봐요 — 2001년 8월 2일 첫 경기…", `kiaCustom` 3장 "이름 뒤엔 타이거즈의 역사".
- **개선 방향:**
  - 프롬프트 예시에서 역사·입문을 뺀다.
  - 유형 다양성 기준을 "유형 4개"가 아니라 "서로 다른 현상·장면 4개"로 바꾼다.
  - 역사는 현상을 이해하는 데 필요할 때 한 장 이하로만 둔다(E1·E3).
- **회귀 테스트:** 기록된 KIA·치이카와 방향 세트에서 history 방향 수와, 역사 문장이 들어간 슬라이드 수를 기준선으로 남긴다.

## 3. 그 밖에 확인한 점
