# EDITORIAL ENGINE V3 · E0 — Editorial Quality Rubric

작성일 2026-11-04 · 코드 변경 없음

## 0. 이 루브릭의 위치

- **두 층으로 나눈다.**
  - **필수 통과 조건(Gate)**: 하나라도 실패하면 점수와 관계없이 게시 불가. 점수로 상쇄할 수 없다.
  - **품질 점수(Score)**: 10개 항목을 1~5점으로 매긴다. 편집 판단을 돕는 참고 값이다.
- **점수의 출처를 반드시 표시한다.** 한 항목을 누가 매겼는지 섞지 않는다.
  - `rule`: 결정적 규칙
  - `ai-review`: AI 편집 리뷰 참고 점수
  - `user`: 사용자 평가
- **AI 리뷰 점수를 사용자 만족도나 실제 성과로 취급하지 않는다.** 실제 성과(저장·공유)는 게시 후 사용자가 입력한 값만 쓴다.
- 기존 품질 게이트(`lib/editorial-quality.ts`의 필수 검증·편집 신호)와 편집 리뷰 점수 5개(hook·specificity·story·save_share·voice)를 **대체하지 않고 확장**한다. 대응표는 5절.

## 1. 필수 통과 조건(Gate)

| ID | 조건 | 실패 예 | 판정 방법(제안) | 현재 코드 |
|---|---|---|---|---|
| G1 | **허위 사실 없음** | 근거 없는 창단일·수치·인용을 단정 | 사실 문장마다 근거 ID 또는 "검증 필요" 표시. 근거 없는 단정이 남으면 실패 | 있음(`facts` 필수 검증) |
| G2 | **허위 경험 없음** | "직접 먹어봤는데", "가 보니", "써 보니" (TREND RADAR가 경험하지 않음) | 1인칭 체험 표현 검출. 사용자 경험 자료(USER_MATERIALS)가 있고 그 출처를 밝힐 때만 허용 | **없음** |
| G3 | **근거 없는 바이럴 주장 없음** | "요즘 난리난", "대세", "SNS에서 핫한", "바이럴" | 인기·확산 표현 검출. 현상 상태가 OBSERVED이고 독립 출처가 2곳 이상일 때만 "여러 곳에서 보여요" 수준 허용. "1위·급상승"은 수치 근거가 있을 때만 | 일부(WHY 분석·잠금 EMERGING 지시만) |
| G4 | **핵심 문화 현상 왜곡 없음** | 아웃송 응원인 삐끼삐끼를 출처 없이 "챌린지 춤"으로만 소개, Virtual→Real을 게임 안 아이템 구매로 뒤집음 | 잠금(현상·행동·방향) 이탈 검사 + 금지 이탈 규칙 | 잠금이 있을 때만(`context-lock`) |
| G5 | **실제 사진과 AI 이미지의 출처 혼동 없음** | AI 생성 이미지를 실제 사례 사진처럼 배치·서술, 실제 근거 이미지를 복제 | AI 이미지 라벨, REAL REFERENCE 링크 전용, 문구에서 AI 이미지를 사례로 지칭하지 않음 | 있음(이미지 라벨·EVIDENCE_GUARD). 문구 쪽 검사는 없음 |

기존 필수 검증(언어 일관성·근거 ID 유효성·중복)은 그대로 유지한다.

## 2. 품질 점수(1~5)

공통 해석:
- **5** = 레퍼런스 수준, 그대로 게시 가능
- **3** = 쓸 만하지만 한 군데 손봐야 함
- **1** = 다시 기획

| # | 항목 | 5점 | 3점 | 1점 | 측정 보조(규칙) |
|---|---|---|---|---|---|
| S1 | **Phenomenon Specificity** | 주체·행동·대상이 한 문장으로 정의된 현상 하나("아바타 눈매를 현실 얼굴에 그림") | 범위는 좁혔지만 행동이 흐림("로블록스 메이크업") | 키워드 자체("메이크업", "기아 타이거즈") | 잠금/브리프에 subject·action·object가 모두 채워졌는가 |
| S2 | **Reader Value** | 독자 가치가 한 문장이고 그 근거(동선·비교 기준·장면 목록)가 슬라이드에 있음 | 가치는 말했지만 근거가 부족 | 무엇을 얻는지 알 수 없음(리포트형) | 브리프의 reader_value 유형과 해당 유형의 필수 요소 존재 여부 |
| S3 | **Information Density** | 본문 슬라이드마다 이 소재에만 있는 디테일(이름·장소·숫자·장면) 1개 이상, 근거 있음 | 절반 정도 | 디테일 없이 감정·일반 조언 | 기존 스왑 테스트(`isGenericSentence`), 근거 있는 디테일 비율 |
| S4 | **Hook Quality** | 제목이 핵심 디테일을 담고 대표 이미지와 같은 대상을 가리킴, 다른 소재로 바꾸면 성립하지 않음 | 구체적이지만 디테일이 약함 | 템플릿 제목("‹소재›, 뭐부터 볼까?") | 기존 `isGenericTitle`·제목 구조 + 제목에 브리프 핵심 디테일 포함 여부 |
| S5 | **Narrative Flow** | 각 장이 새 정보를 하나씩 더하고 다음 장으로 넘길 이유(to_next)가 있음 | 한두 장이 반복 | 같은 결론의 반복 또는 분석 순서 나열 | 기존 중복 검사 + 장별 new_information 겹침(E2) |
| S6 | **Cultural Accuracy** | 팬덤·밈의 내부 맥락(언제·누가·왜)을 정확히 전달 | 맥락 일부 생략 | 외부인의 일반 설명으로 바꿈, 왜곡 | 잠금의 culturalContext 반영, 편집 리뷰 |
| S7 | **Visual Relevance** | 슬라이드 이미지가 그 슬라이드 메시지의 장면(주체가 행동하는 모습)을 보여 줌 | 주제와는 맞지만 슬라이드 메시지와 어긋남 | 일반 주제 사진·로고·다른 슬라이드 이미지 | 이미지 브리프(subject/action/object) 채움 여부 — 실제 이미지 판정은 사람 |
| S8 | **Editorial Voice** | 자연스러운 해요체, 보고·조사 서술 없음 | 한두 문장이 딱딱함 | 보고서·보도 요약체 | 기존 `REPORT_PHRASES`·`SOURCE_NARRATION` + 조사·통계 서술 검출 |
| S9 | **Evidence Integrity** | 사실·관측 사례·가설이 문장에서 구분됨(“이런 영상이 있어요”, “이런 게 있다면”) | 구분은 있지만 일부 단정 | 가설을 사실처럼 씀 | fact_checks 상태 분포, concept_notice |
| S10 | **Save/Share Potential** | 저장(리스트·동선·비교표) 또는 공유(공감·대화 소재) 이유가 구조로 드러남 | 이유는 있으나 약함 | 이유 없음 | reader_value 유형이 save/share 계열인지 + 마지막 장 CTA가 그 가치와 연결되는지 |

## 3. 판정 규칙

1. Gate G1~G5와 기존 필수 검증을 먼저 본다. 하나라도 실패하면 **"게시 전 수정 필요"**이고 점수는 참고로만 보여 준다.
2. 점수는 항목별로 출처(rule / ai-review / user)를 함께 저장하고, 화면에도 출처를 표시한다.
3. 종합 점수(평균)를 대표 숫자로 내세우지 않는다. **가장 낮은 두 항목**을 "다음에 고칠 것"으로 보여 준다.
4. 같은 콘텐츠를 다시 생성해 비교할 때는 Gate 통과 여부, S1·S2·S3(규칙 측정 가능한 항목), 사람 평가 순서로 본다. AI 리뷰 점수만으로 "개선됐다"고 보고하지 않는다.

## 4. 평가 절차(사람 평가용)

- **평가자:** 콘텐츠를 만든 사용자, 또는 팀 편집자 1명 이상
- **입력:** 완성 카드뉴스(문구 + 이미지), 브리프(E1), 근거 원장
- **방법**
  1. 평가자는 Gate를 체크리스트로 확인한다.
  2. S1~S10을 매긴다. 각 점수에 한 줄 이유를 적는다.
  3. AI 리뷰 점수와 다른 항목은 차이를 기록한다(리뷰 기준 보정용).
- **게시 후 선택 입력:** 저장·공유 수. 성과 비교에만 쓰고 품질 점수와 섞지 않는다.

## 5. 기존 코드와의 대응

| 루브릭 | 기존 | 비고 |
|---|---|---|
| G1 | 필수 `facts` | 유지 |
| G2 | 없음 | E4에서 추가 |
| G3 | WHY 분석(`openai-analysis.ts`)·잠금 EMERGING 지시 | 제작 단계 검사 추가 |
| G4 | 필수 `context-lock`(잠금 있을 때) | 경량 잠금으로 넓힘(E1) |
| G5 | 이미지 라벨·EVIDENCE_GUARD | 문구 검사 추가 |
| S1 | 없음 | 브리프 필드 채움 여부 |
| S2 | 편집 신호 `flow`(reader_gets 비었는지) | 유형·근거 요소 검사로 확장 |
| S3 | 편집 신호 `specific`·`detail-use` | 유지 + 근거 있는 디테일 비율 |
| S4 | 편집 신호 `title`, 리뷰 `hook` | 제목·디테일·이미지 일치 추가 |
| S5 | 필수 `duplicate`, 리뷰 `story` | new_information 겹침 추가 |
| S6 | 없음(잠금 일부) | 리뷰 항목 추가 |
| S7 | 없음 | 브리프 기반 규칙 + 사람 판정 |
| S8 | 편집 신호 `not-report`, 리뷰 `voice` | 조사·통계 서술 추가 |
| S9 | fact_checks 상태, concept_notice | 유지 |
| S10 | 리뷰 `save_share` | reader_value 유형과 연결 |
