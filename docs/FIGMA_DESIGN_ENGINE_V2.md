# Figma Design Engine V2

작성일: 2026-11-02

## D0. 현재 디자인 진단 (`figma-plugin/code.js` `buildFigmaPlan`·`renderPlan`, `lib/figma-export.ts`)

사용자가 실제 Figma 앱에서 확인한 결과(6개 프레임 생성, 디자인 완성도 낮음)를 코드로 추적한 결과다.

| 항목 | 현재 구현 | 결과에 미친 영향 |
|---|---|---|
| 1. 프레임 크기 | 캔버스 그대로(4:5 = 1080×1350) | 정상 |
| 2. 텍스트 레이어 | 역할별(headline·body·caption·cta) 텍스트를 한 열로 쌓음 | 위계가 "글자 크기 차이"뿐 |
| 3. 폰트 크기·줄 높이 | `DEFAULT_TOKENS` 고정: 헤드라인 64px, 본문 34px, 보조 24px, CTA 36px(1080 기준), 행간 1.2~1.5. 길이와 무관 | 헤드라인이 프레임 폭의 약 6% → 모바일에서 작음. 표지와 본문 슬라이드가 같은 크기 |
| 4. 자동 줄바꿈 | 고정 폭 + `textAutoResize: HEIGHT` | 줄바꿈은 되지만 단어 단위 조정 없음 |
| 5. 오버플로 | 검사 없음. 넘치면 `clipsContent`로 잘림 | 긴 본문이 프레임 밖으로 나가 잘릴 수 있음 |
| 6. 이미지 | 슬라이드에 `image_ref`가 있을 때만. 실제 근거 이미지는 점선 자리표시, AI 이미지는 사용자가 직접 생성한 경우만 | 대부분 이미지 없음. 근거 이미지 슬라이드는 하단 절반이 빈 점선 상자 |
| 7. 배경 | 표지만 `color.surface`(#EEF1FF), 나머지는 `color.background`(#FFFFFF) | 대부분 흰 배경 |
| 8. 디자인 토큰 | 웹사이트(Y2K XP) 토큰 하나를 모든 콘텐츠에 사용, Visual DNA·톤·모드 무시 | 소재마다 디자인이 같음 |
| 9. 슬라이드 타입 | 템플릿 6종(cover-fullbleed, text-top-image-bottom, text-only, quote-card, cta-end, video-frame) — 대부분 `text-only`/`text-top-image-bottom` | 슬라이드 간 변화 없음. 이미지 참조가 있으면 텍스트가 상단 고정 |
| 10. Studio가 주는 디자인 정보 | `visual_direction`·`layout_hint`(문장)만 — 레이아웃에 쓰이지 않고 plugin data에만 저장 | 기획한 비주얼 방향이 디자인에 반영되지 않음 |
| 11. JSON vs Direct Handoff | 같은 `toFigmaExport`. Handoff만 `handoff` 블록과 24시간 서명 링크 | 차이 없음(둘 다 디자인 정보 부족) |
| 12. 기존 노드 보호·중복 | 기존 노드 오른쪽 배치, 같은 작업 재생성 차단, 실패 슬라이드만 제거 | 정상 — 유지 |

핵심 원인: **디자인을 "기획"하는 단계가 없었다.** 플러그인이 텍스트를 고정 크기로 쌓기만 했고, Studio는 레이아웃·색·이미지 배치를 결정하지 않았다.

## 설계 방향

- **Studio(웹)가 디자인을 기획한다** — `lib/card-design.ts`: 스타일·색·타이포·간격 토큰 → 슬라이드별 레이아웃(L01~L08) 선택 → 텍스트 길이에 맞춘 크기 계산 → 프레임별 장면(scene: 사각형·원·텍스트·이미지 요소의 위치·크기·색·폰트)을 만든다.
- **플러그인은 장면을 편집 가능한 노드로 구현한다** — 텍스트·이미지·배경·그래픽을 각각 별도 레이어로. 실제 Figma 글꼴로 잰 높이가 상자를 넘으면 그 자리에서 글자를 줄이되 최소 크기 아래로는 내리지 않고, 그래도 넘치면 경고한다.
- 같은 장면을 웹 미리보기(HTML)로도 그려 Studio에서 확인하고 PNG로 점검한다(실제 Figma 렌더링과는 글꼴 측정이 다를 수 있다).
- 하위 호환: 내보내기 JSON에 `design` 블록을 **추가**한다. 플러그인은 `design`이 없으면 기존 방식으로 그린다.

## D1. 디자인 시스템 (`lib/card-design.ts`)

- **색 토큰 7종**: primary · secondary · accent · background · surface · textPrimary · textSecondary. 스타일 기본값 → (자동일 때) Visual DNA 관찰 색으로 강조·배경·주색을 바꿈 → 대비 보정. 출처를 `colorSources`에 남긴다(`observed` = 썸네일에서 관찰한 색, `rule` = 규칙 해석, `style` = 스타일 기본).
- **대비**: 모든 텍스트를 "바로 아래 칠"(카드·버튼·컬러 블록·배경) 기준으로 큰 글자 3, 작은 글자 4.5 이상으로 맞춘다. 이미지 위 글자는 그라데이션 오버레이가 맡는다.
- **타이포 6역할**(1080 폭 기준 최대~최소): Display 156~92 · Section 96~64 · Body 44~34 · Supporting 32~26 · Caption 26~22 · CTA 40~32. 길이에 맞춰 이 범위에서 가장 큰 크기를 고르고, 최소에서도 넘치면 **레이아웃을 바꾼다**(문구 삭제 없음). 제목은 줄 길이가 고르게 나뉘도록 줄바꿈을 넣고, 한 글자 수식어(한·두·첫…)가 줄 끝에 남지 않게 한다.
- **간격**: 안전 여백 = 폭의 9% / 7.5% / 6.2%(여유·균형·촘촘), 요소 간격 40 / 32 / 24px.
- **위계**: 메인 비주얼/후킹 → 제목 → 핵심 정보 → 보조 → CTA 순으로 크기·위치·색 대비를 둔다. 페이지 번호·시리즈 표시로 묶는다.

## D2. 레이아웃 엔진

L01 HERO COVER · L02 EDITORIAL STORY(이미지형/번호형) · L03 FULL BLEED IMAGE · L04 SPLIT(이미지 또는 컬러 블록 + 키워드) · L05 INFORMATION CARDS(본문 + 칩 카드) · L06 LIST(본문 문장 → 번호 항목, 줄 수에 비례한 높이) · L07 BIG STATEMENT · L08 CLOSING/CTA(버튼 + 저장·공유·댓글).
선택: 첫 장 L01(이미지 비중 높음 + 이미지면 L03), 마지막 L08, 그 사이는 내용 모양(보조 문구 항목 수, 본문 문장 수, 짧은 문장, 슬라이드 유형, 이미지)으로 후보를 만들고 **직전과 같은 레이아웃·두 번 쓴 레이아웃을 뒤로** 미룬다. 이미지가 있는 슬라이드는 이미지 레이아웃을 먼저 시도한다. 넘치면 다음 후보.

## D3. 트렌드별 스타일

스타일 6종(Minimal Editorial · Bold Typography · Kitsch Pop · Retro Digital · Contemporary Magazine · Playful Graphic)과 모티프 6종(가는 선 · 사선 스트라이프 · 스티커 · 픽셀 블록 · 뷰파인더/REC · 둥근 도형). 자동 추천 = 소재·방향 단어(×2) + 사용자 톤(+5) + Visual DNA 관찰 특징(×1). 톤을 바꾸면 같은 소재도 다른 스타일이 될 수 있다(예: 발레코어 "에세이처럼 차분하게" → Minimal Editorial, "팬의 마음으로 유쾌하게" → Playful Graphic). 구단 로고·공식 그래픽은 쓰지 않는다(일반 스포츠 모티프만).

## D4. 이미지

우선순위: 슬라이드에 사용자가 연결한 AI 이미지 → (표지만) 프로젝트의 남는 AI 이미지 → 그래픽(색 블록·타이포·도형). 실제 근거 이미지는 복제하지 않고 "참고 이미지 · 원본 링크는 Editor Notes" 표시만. 이미지는 `FILL`(비율 유지·자르기), 위에 글자가 오면 그라데이션 오버레이. 불러오기 실패 시 대체 색 블록 + 레이어 이름에 표시. **AI 이미지는 자동 생성하지 않는다.**

## D5. Studio 설정

카드뉴스 형식일 때 DESIGN 패널: 디자인 스타일(자동 추천 표시) · 색(자동/스타일 기본/모노톤/비비드) · 글자 분위기 · 이미지 비중 · 밀도. 비율은 기존 "비율" 설정. 생성 결과 위에 DESIGN PREVIEW(같은 장면을 HTML로)와 스타일·색 출처·레이아웃 메모.

## D6. 편집 가능한 Figma 생성 (`figma-plugin/code.js`)

`design`이 있으면 장면 요소마다 별도 노드: 사각형·원(색·투명도·모서리·외곽선·회전), 그라데이션 사각형, 이미지 사각형(IMAGE fill), 텍스트(글꼴 → Noto Sans KR → Inter 대체). 텍스트는 실제 글꼴로 잰 높이가 상자를 넘으면 최소 크기까지 줄이고, 그래도 넘치면 결과 화면에 "글자 넘침" 경고. 프레임 전체를 이미지로 합치지 않는다. 기존 노드 보호·중복 생성 차단·부분 실패 처리·JSON/Direct Handoff·이전 JSON(legacy) 그대로.

### 실제 Figma에서 확인할 것(사용자 테스트 절차)

1. `npm run dev` 후 Content Studio에서 카드뉴스 프로젝트를 열고 DESIGN PREVIEW 확인 → "Figma로 보내기"(또는 JSON 내보내기).
2. Figma 데스크톱에서 플러그인 실행 → 작업 선택 → 카드뉴스 만들기. 결과 메시지에 "Studio 디자인 적용"이 보이는지.
3. 확인 목록: ① 프레임 6장 1080×1350 ② Black Han Sans·Jua·Do Hyeon·Noto Serif KR이 적용됐는지(없으면 결과에 "폰트 대체") ③ 사선 스트라이프·스티커 회전 방향과 위치 ④ 그라데이션이 아래로 갈수록 어두운지 ⑤ 글자가 상자를 넘치지 않는지(넘치면 "글자 넘침" 경고) ⑥ 텍스트·이미지·배경을 각각 선택·수정 가능한지 ⑦ 프레임 선택 → Export PNG 2x 품질.
4. 웹 미리보기와 다르게 보이는 곳(줄바꿈·회전·그라데이션)을 알려 주시면 그 부분을 맞추겠습니다.

## 남은 한계

- Figma 앱 렌더링은 확인하지 못했다. 회전 기준(왼쪽 위, 반시계)·그라데이션 방향·글꼴 이름(스타일명)은 문서 기준으로 구현했고 실제 앱에서 다를 수 있다.
- 글자 크기 추정은 글자 폭 근사(한글 0.95em)라 실제 글꼴과 다르다. 플러그인이 실제 높이로 한 번 더 줄이지만, 늘리지는 않는다.
- 스티커·픽셀 장식은 매 장 같은 자리에 반복돼 단조롭다. 키치 스타일의 "레이어드" 느낌은 아직 약하다.
- 디자인 품질은 템플릿 수준이며 디자이너의 판단을 대신하지 않는다. 미리보기 점검도 개발자의 시각 확인이지 사용자 평가가 아니다.
