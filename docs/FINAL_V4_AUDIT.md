## 1. 여섯 가지 질문에 대한 답

1. **기능은 있지만 이해하기 어려운 곳**
   - 온보딩(WELCOME.EXE)이 5단계를 차례로 소개한다. 그래서 모든 단계를 거쳐야 하는 것처럼 보인다.
   - 진행 막대가 하나의 직선 경로(찾기 → WHY → DNA → 섞어 보기 → 기획안)만 보여 준다.
   - MY TEMPLATES의 동기화·렌더링 버튼이 웹이 아니라 Figma 플러그인 안에 있다는 점을 처음에는 알기 어렵다(실사용 질문으로 확인).
2. **다음 행동을 정하기 어려운 화면**
   - 진행 막대의 "다음" 버튼이 단일 트렌드 제작에도 DNA·Collision을 다음 단계로 권한다.
   - 근거가 부족한 방향을 고른 뒤 제작이 실패하면 대안을 안내하지 않는다(치이카와 사례).
3. **콘텐츠 품질이 떨어지는 근본 원인** ([EDITORIAL_FAILURE_ANALYSIS.md](EDITORIAL_FAILURE_ANALYSIS.md))
   - 방향 제안의 기본값이 키워드의 역사·입문이었다(V3에서 수정, 실측으로 효과 확인).
   - 현상 정보가 한 경로(현상 선택)로만 전달됐다(V3에서 경량 잠금으로 확장).
   - 근거가 부족하면 제작자 메모가 게시 문구에 새어 나온다(V3 실측에서 발견, 검사·지시 추가, **재생성 확인 전**).
4. **콘텐츠와 이미지가 어긋나는 곳**
   - 잠금이 없을 때 이미지 브리프의 주체가 콘텐츠 제목이 돼, 모든 슬라이드가 비슷한 일반 이미지가 되기 쉬웠다(V3 E2에서 슬라이드 장면 우선으로 수정).
   - 편집 리뷰가 문구를 고쳐도 이미지 지시는 그대로다(미수정, P2).
5. **저장·화면 이동에서 데이터가 유실될 가능성 — 있음(P0)**
   - 브라우저 저장 공간이 차면 저장 실패를 화면이 모른다.
   - Content Studio에 Collision을 다른 분석으로 바꿔치는 코드가 남아 있었다.
6. **기존 테스트가 확인하지 못하는 실제 경험**
   - 저장 공간이 가득 찬 브라우저
   - 오래 켜 둔 개발 서버가 예전 모듈을 쓰는 상황(실사용에서 두 번 발생)
   - 실제 Figma 렌더링, 실제 콘텐츠의 재미
