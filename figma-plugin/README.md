# TREND RADAR Studio Import (Figma 플러그인)

Content Studio의 작업을 Figma 프레임으로 만든다. 빌드 과정이 없다(순수 JS). 전체 구조와 검증 범위는 `docs/FIGMA_DIRECT_EXPORT.md`.

## 설치(개발용, 로컬)

1. Figma 데스크톱 앱 → Plugins → Development → **Import plugin from manifest…** → 이 폴더의 `manifest.json`
2. TREND RADAR를 `npm run dev`(http://localhost:3000)로 실행 — 개발 도메인은 `devAllowedDomains`에 있다.
3. 배포 서버를 쓰려면 `manifest.json`의 `allowedDomains`에 그 도메인을 추가하고, 플러그인 **설정 → 서버 주소**를 바꾼다.

## 사용

**TREND RADAR에서 가져오기(기본)**
1. Content Studio에서 **Figma로 보내기** → 작업 코드 확인
2. Figma에서 플러그인 실행 → 처음 1회 **TREND RADAR 연결**(브라우저에서 허용)
3. 가장 최근 작업이 자동 선택된다(코드 확인) → **카드뉴스 만들기**

**JSON 파일**: Studio의 “Figma JSON 내보내기” 파일을 선택하거나 붙여넣는다(계정 불필요).

한 번 만든 파일에는 “TREND RADAR 작업 가져오기” 재실행 버튼이 생긴다.

## 만들어지는 것

| 데이터 | Figma |
|---|---|
| 슬라이드·장면 | 프레임(캔버스 크기 그대로), 이름 `TR <코드> · 01 · cover`. 현재 페이지 기존 내용의 오른쪽에 추가(기존 노드는 그대로) |
| 텍스트 | 텍스트 레이어. 글꼴: 토큰 → fallback → Noto Sans KR → Inter, 대체 내역 표시 |
| AI 생성 이미지 | IMAGE fill, 레이어 이름 "AI 생성 이미지 — 실제 사진 아님" |
| REAL REFERENCE | **복제하지 않음** — 원본 링크가 적힌 점선 자리표시 |
| 근거 ID·디자인 메모 | 프레임 plugin data(`trend-radar`), 작업 ID는 `trend-radar-handoff` |
| 캡션·해시태그·이미지 권리 | 왼쪽 NOTES 프레임 |

같은 작업을 같은 페이지에 다시 만들려 하면 막고, 확인 버튼을 눌러야 한 번 더 만든다.

## MY TEMPLATES (내 템플릿으로 출력)

플러그인 창 위쪽 **EXPORT MODE**에서 고른다. **AUTO DESIGN**은 위의 기존 방식(Studio가 기획한 디자인), **MY TEMPLATES**는 이 파일의 템플릿을 복제해 내용을 넣는다.

1. 파일에 이름이 정확히 `Templates`인 페이지를 만들고, 그 페이지 맨 위 단계에 프레임 8개를 둔다:
   `TEMPLATE_COVER_01~03` · `TEMPLATE_BODY_01~03` · `TEMPLATE_CTA_01~02`
2. 프레임 안에서 내용이 들어갈 레이어 이름을 아래처럼 정한다(템플릿마다 필요한 것만 있으면 된다).

| 레이어 이름 | 종류 | 들어가는 내용 |
|---|---|---|
| `TITLE` | 텍스트 | 슬라이드 제목 |
| `SUBTITLE` | 텍스트 | 보조 문구 |
| `BODY` | 텍스트 | 본문 |
| `CATEGORY` | 텍스트 | 잠근 현상의 상위 키워드 또는 소재 이름 |
| `PAGE_NUMBER` | 텍스트 | `03 / 06` |
| `CTA` | 텍스트 | 슬라이드 CTA(없으면 Studio 설정의 CTA, CTA 슬라이드만) |
| `IMAGE_MAIN` | 사각형·프레임 등 채우기가 있는 레이어 | 이 슬라이드의 대표 이미지 |
| `IMAGE_1`, `IMAGE_2`, `IMAGE_3`, `IMAGE_4` | 〃 | 각자 다른 사진 칸: Studio “추가 이미지”를 번호 순서대로(`IMAGE_MAIN`이 없는 템플릿은 대표 이미지가 `IMAGE_1`). 없으면 회색 자리표시 + 이유. `IMAGE1`·`IMAGE_01`·`img-1`도 인식(이름을 고치라고 안내) |
| `BG_IMAGE` (`IMAGE_BG`, `BACKGROUND_IMAGE`도 인식) | 〃 | 배경 이미지: “배경”으로 고른 이미지, 대표 슬롯이 없는 템플릿이면 대표 이미지. 꽉 채움(FILL) |
| `BG_COLOR` | 단색 채우기가 있는 레이어(숨겨도 됨) | 배경 이미지가 없을 때 쓸 색(내용은 넣지 않음) |

- **배경 슬롯**: `BG_IMAGE` 또는 프레임 넓이의 90% 이상을 덮는 `IMAGE_MAIN`. 넣을 이미지가 없으면 회색 자리표시 대신 단색으로 채운다 — `BG_COLOR` 레이어 → 템플릿 프레임 배경 → 프로젝트 팔레트 대표색 → `#F5F5F5`. 그 위의 그라데이션·오버레이와 텍스트는 그대로. 템플릿 프레임 자체가 투명하면 복제본 프레임에만 같은 규칙의 색을 깐다(체크보드가 남지 않게).
- **여러 이미지**: `BG_IMAGE` ← “배경” 이미지 → 없으면 대표(MAIN) 이미지(대표 슬롯에 같은 사진이 들어가도) → 이미지가 없으면 단색. `IMAGE_2~4`는 대표·배경 외 나머지를 순서대로. 넣을 자리가 없는 이미지는 결과에 알린다. 자동 배정은 이미지 수에 맞는 템플릿(2장 → 이미지 2칸)을 고른다.
- 생성 전 점검은 템플릿마다 배경 슬롯 유무, 일반 이미지 슬롯 수, 제목·본문 슬롯 유무, 배경 대체 색의 출처를 보여 준다. `BG_IMAGE`만 있는 표지 템플릿도 정상 템플릿이다.

- MY TEMPLATES를 고르면 **생성 전 점검** 결과를 보여 준다: 찾은/없는 템플릿, 이름 오류, 레이어 종류 오류, 템플릿마다 쓰는 글꼴과 **설치되지 않은 글꼴 이름**, 슬롯으로 인식되지 않은 텍스트 레이어(견본 문구가 그대로 남을 곳, `STATIC_`으로 시작하는 고정 문구는 제외), 이미지가 불투명한 채우기에 가려질 슬롯. 이번에 쓸 템플릿에 경고가 있으면 만들기 전에 한 번 더 확인을 받는다. 슬롯 이름은 대소문자·공백·하이픈 차이(`Image Main`)도 인식하되 정확한 이름으로 바꾸라고 안내한다.
- 슬라이드마다 템플릿을 고를 수 있다. 기본값 AUTO는 표지→COVER, CTA·마무리→CTA, 나머지→BODY 중 이미지 유무가 맞는 것을 고르고, 바로 앞 슬라이드와 같은 템플릿은 피한다.
- **원본은 바꾸지 않는다.** 슬라이드마다 원본을 복제하고 복제본에만 넣는다. `Templates` 페이지에서 실행하면 새 페이지(`TREND RADAR · 제목`)에, 다른 페이지에서는 그 페이지 기존 내용 오른쪽에 만든다.
- 글꼴은 템플릿 것을 그대로 쓴다. 레이어가 쓰는 글꼴을 모두 불러온 뒤 고친다. 글꼴이 설치되지 않은 레이어는 기본으로 **템플릿 글꼴을 바꾸지 않고 숨긴다**(견본 문구가 결과물에 남지 않게) — 결과에 없는 글꼴 이름을 알린다. "글꼴이 없는 텍스트에 대체 글꼴 쓰기"를 켜면 그 레이어만 고른 글꼴(Noto Sans KR·Pretendard)로 바꿔 넣는다. 레이어 이름은 바꾸지 않는다.
- 글자가 상자를 넘치면 원래 크기의 85%(최소 12px)까지만 줄이고, 그래도 넘치면 결과에 알린다(레이어 plugin data `trend-radar-template`에 `overflow`). 글자를 자르지 않는다.
- 빈 내용(예: 보조 문구 없음)의 레이어는 숨긴다(견본 문구가 남지 않게).
- 이미지: 슬롯이 그룹이면 안쪽의 견본 사진 레이어(없으면 가장 큰 레이어), 프레임 안에 견본 사진 레이어가 있으면 그 레이어에 넣는다. 템플릿의 IMAGE 채우기 자리에 넣고, IMAGE 채우기가 없으면 맨 아래 단색(이미지 자리표시 바탕)을 이미지로 바꾸고(결과에 알림), 그것도 없으면 맨 아래에 넣는다. 그라데이션·오버레이 채우기는 그 위에 그대로 둔다(FILL: 비율 유지·슬롯 채움). AI 이미지에는 "AI 생성 이미지" 표시를 단다.
- 이미지를 넣지 못한 슬롯은 견본 사진만 회색으로 바꾸고(오버레이 유지) 슬롯 위와 결과에 이유를 적는다: 이 슬라이드에 연결된 이미지 없음 / 이미지 파일을 받지 못함(만료 등 사유) / 실제 근거 이미지라 복제 안 함.
- 자동 배정은 종류별 슬라이드 수만큼만 템플릿을 쓴다(예: 표지 1·본문 4·CTA 1 → 최대 5종). 결과에 그 설명을 함께 보여 준다.
- 맞는 종류의 템플릿이 없는 슬라이드는 그 슬라이드만 AUTO DESIGN으로 그린다.

## SYNC MY TEMPLATES · 웹 미리보기 (Content Studio 갤러리)

먼저 Supabase SQL Editor에서 `supabase/migrations/202611040010_figma_templates.sql`을 실행한다(0009 다음).

1. 플러그인에서 TREND RADAR에 연결한 뒤 MY TEMPLATES → **SYNC MY TEMPLATES**. 템플릿 8종을 `exportAsync`로 PNG(가로 480px, 너무 크면 320px)로 내보내 계정에 등록한다. 원본 프레임은 읽기만 한다. 연결하지 않으면 동기화할 수 없다.
   - 저장: 템플릿 이름(ID)·유형·크기·슬롯(이미지 슬롯 수, 배경 슬롯)·Figma 파일 이름/키·노드 ID·썸네일·디자인 지문·버전·동기화 시각. 사용자당 템플릿 이름별 1행(다시 누르면 덮어쓰고, 디자인이 바뀌었을 때만 버전이 오른다).
   - 내보내기에 실패한 템플릿은 이전 썸네일을 지우지 않고 SYNC FAILED, Templates 페이지에서 사라진 템플릿은 MISSING TEMPLATE.
2. Content Studio → DESIGN SOURCE에서 **MY TEMPLATES** → 갤러리(썸네일·유형·이미지 슬롯 수·동기화 시각·상태)와 슬라이드별 템플릿 선택. 선택은 프로젝트에 저장되어 Workspace·다른 브라우저(로그인 계정)·“Figma로 보내기”·플러그인 기본 선택으로 이어진다. 웹은 템플릿 원본을 바꾸지 않는다.
3. 미리보기는 두 가지를 구분한다.
   - TEMPLATE PREVIEW: 동기화한 원본 템플릿 썸네일(콘텐츠 미적용).
   - RENDERED CONTENT PREVIEW: “Figma로 보내기” 후 플러그인에서 작업을 고르고 **미리보기 렌더링 → 웹**. 임시 페이지에 복제본을 만들어 내용을 넣고 PNG로 보낸 뒤 그 페이지를 지운다. 내용·템플릿·템플릿 버전이 바뀌면 웹에 “이전 렌더링 — 최신 렌더링 필요”로 표시된다. 웹이 HTML로 템플릿을 흉내 내지 않는다.
4. 상태: Figma 원본 변경은 플러그인을 열어 MY TEMPLATES 점검을 할 때만 알 수 있다(디자인 지문 비교). 그때 다르면 UPDATE AVAILABLE, 그 밖에는 SYNCED와 마지막 동기화 시각만 보여 준다. 웹의 새로고침은 저장된 목록을 다시 읽을 뿐 Figma를 실행하지 않는다.
- 썸네일·렌더링 PNG는 공개·서명 링크 없이 DB(본인만 읽기, RLS)에 두고 로그인 토큰으로 서버 API를 거쳐 받는다(만료되는 링크가 없다). 렌더링 미리보기는 프로젝트·슬라이드별 최신 1장, 사용자당 최대 300장.

## 검증 범위

`tests/figma-plugin.spec.ts`, `tests/figma-direct.spec.ts`, `tests/figma-templates.spec.ts`가 실제 `ui.html`·`code.js`를 가짜 `figma` API로 실행해 검사한다(MY TEMPLATES: 페이지 지연 로딩·복제·글꼴 로딩 규칙·mixed 글꼴·없는 글꼴·자동 높이 측정을 흉내 냄). **실제 Figma 앱에서의 실행·편집·PNG 내보내기는 사용자가 확인해야 한다.**
